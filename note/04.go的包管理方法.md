## Go 包管理困境

go 1.11 版本之前

- 没有统一的包挂历方式
- 包之间的依赖关系很难维护
- 如果同时需要一个包不同版本，非常麻烦。

尝试解决办法
godep、govendor、glide 等解决。

为彻底解决 GOPATH 存在的问题。 非常麻烦

go 1.11 之后的版本

Go modules 最新的包管理方式；类似于 js 的 npm

本质上，一个go 包就是一个项目源码（是源码）

gomod 的作用： 将 Go 包和 Git 项目关联起来
go 包的版本就是 git 的tag

go get github/xxxx [ @version \]

使用本地文件代替

go.mod 文件追加:
replace github.com/Jeffail/tunny => xxx/xxx

## 创建 Go Module

1、删除本地的 go.mod

2、执行 go mod init github.com/imooc/moody
3、推送至远程仓库
4、增加新版本时；在仓库打新 Tag 即可。
