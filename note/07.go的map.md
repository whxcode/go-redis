## 2. 链式/拉链法

底层数据不直接存储数据；只存一个链表指针；把具体数据存储到链表上。
查找方式: 根据hash找到链表；在遍历链表对比 key。

go 的 map 的存的是key的第1个字节的hash值。

# 扩容问题

- hash 碰撞
- map 的溢出桶太多的时候；会导致严重的性能下降。
- runtime.mapassign() 可能会触发扩容情况

  - 装载英子太多了
  - 溢出桶太多了

- 等量扩容 => 整理数据
- 翻倍扩容 => 数据太多了；平衡hash

- 扩容步骤 1 调用 hashGrow

1. 创建一组新桶 newbuckes。
2. oldbukect 指向原来的 buckets
3. buckets 指向 newbuckes

- 扩容步骤 2 map 的扩容是采用渐进式的，桶被操作是才会重新分配

1. 将所有数据从旧桶迁移到新桶
2. 在下次更新 key 的值；迁移到 新的桶

# map 的怎么解决并发问题

- map 的读写并发有问题 - 还有可能编译报错。
- A 协程在桶中读取数据，B协程种驱逐了这个桶。(这儿就发生了数据竞争问题)
- 给 map 加锁 (mutex) 但是会严重影响性能
- sync.Map 数据结构；对于 写/读 有很好的性能。但对于大量追加性能不太友好
